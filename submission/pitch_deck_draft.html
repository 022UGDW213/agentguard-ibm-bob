The problem

The confused deputy

Agents are the new attack surface.

  • An agent tricked by a malicious prompt, a poisoned tool description, or a compromised plugin will happily read /etc/passwd or exfiltrate keys — with your credentials.
  • Red-team / blue-team tooling was built for humans, not for software acting at machine speed.
  • Your agent is a deputy with your keys. Anyone who confuses it becomes you.
This month in the real world

CVE-2026-90970 (CVSS 9.9, disclosed Oct 2): a crafted flow config escaped GitLab’s AI Gateway prompt-template sandbox → arbitrary commands on the gateway host. Fixed in 19.2.4 / 19.3.2 / 19.4.1. Agent infrastructure is already the target.

The solution

Deny by default

Policy engine

Explicit rules sit in front of every tool call. Anything unmatched is denied — deny rules beat allow rules.

Capability tokens

Authorization travels as HMAC-signed, narrowly-scoped, expiring tokens bound to the agent. No token, no scope, no call.

Audit ledger

Every decision — allow or deny — lands in an append-only ledger with the reason. Proof of what your agents tried to do.

This is the confused-deputy fix, and it works with any model.

Design

Model-agnostic by design

  • The harness wraps a ModelBackend interface — the same choke point governs local tools, a Bob-driven loop, or any future model.
  • Secure-codebase scanner: secret patterns plus live pip-audit / npm audit — audit is clean, zero known vulnerabilities.
  • Zero-dependency Java SDK with the same HMAC tokens (interop proven both ways) + a JSON module for policies, tokens, audit entries.
  • No stubs, no simulated findings — every component runs for real.

We don’t care which model you use. The guardrail is the same.

Built with IBM Bob

Integration, two directions

Bob → AgentGuard

A real MCP server (check_policy, scan_codebase, audit_summary) on the official MCP SDK; .bob/mcp.json auto-wires it into Bob IDE. Bob reads the codebase and generates the security policies.

AgentGuard → Bob

BobShellBackend drives Bob headlessly via the Bob Shell CLI — a Bob-powered agent loop under the same policy engine. Bob authored the test suite: 90 tests passing, 4 skipped.

Honest note: IBM publishes no public REST API for Bob — CLI + MCP are the verified surfaces, and we built on exactly those. We read the docs; we didn’t invent endpoints.

Architecture

One choke point

Agent ──▶ [ GuardedHarness ] ──▶ Tools / Bob backend
             │ policy engine + token verifier
             ├── sidecar: append-only audit ledger
             └── sidecar: secret + dependency scanner

Deny rules beat allow rules; unmatched calls die. One choke point — that’s the entire security model.
